# 高清主体预览与对照（r10）

初筛工作台保留轻量缩略图栏，主图另外加载高清主体预览。最长边 2048 像素，取自完整解码后的主体范围，不放大小裁切。每个 JPEG 不超过 1 MiB，优先质量 88，复杂画面必要时降低 JPEG 质量。它是看图预览，并不是无损导出或修复后的原片。

## 使用

1. 新扫描或主动重新识别时，复用本次完整解码的画面生成两份预览，不再读一遍原片。这个功能不会让已扫描且未变化的照片重新扫描。
2. 已有照片先显示原有缩略图。点击“生成此图高清预览”，或勾选明确的照片后点“补生成勾选图高清预览”。只补生成所选原有照片的预览，不做鸟种推理、评分、目录扫描或移动。顶部显示逐图进度；失败会停下，已完成的缓存保留，重试复用它们。
3. 默认显示“高清主体 · 自动调整”。“原图”切换到**同一主体裁切、未调整**的 RAW 解码画面；再点“自动调整”返回。“整张原图”仍是单独入口。
4. 框选保存后按新裁切查找缓存，旧裁切不会冒充当前结果；如无匹配预览，再点补生成即可。亮度等手动编辑仍在编辑窗口操作。此预览的自动调整和原图对照均不叠加手动色调，以便保持明确、可重复的对照。
5. 评估清晰度、虚焦或运动模糊时请用“原图”版本，必要时进入编辑窗口查看原始像素。自动调整不是用于判断质量模型效果的输入。

## 显示调整

按画面平均亮度选择温和的阴影提亮与高光压缩，在亮度通道增加少量对比度和局部清晰度。原片、EXIF、人工参数、人工鸟种、标记、星级和正式质量分都不因此改变。无法还原已经丢失的高光或暗部细节，也不能把虚焦变成真实清晰。新鸟眼、遮挡、姿态等质量模型仍未接入正式评分。

## 缓存与空闲占用

- 两个版本存放在独立数据目录 `display-previews.sqlite3`。默认 JPEG 内容预算 512 MiB，可在现有配置增加 `display_preview_budget_mb`（8～4096）；最多 1024 对，生成时按最早生成顺序淘汰。SQLite 页、索引及写入事务日志另有少量开销。不会清理原片或正式图库数据库。
- 缓存配对写入和淘汰使用事务，满额时不影响原有缩略图。读取缓存不更新访问时间、不写数据库。看图只核对源文件授权、存在、大小、修改时间和裁切版本；补生成时还会完整核对前后 SHA-256。刻意保留相同大小与修改时间的文件替换无法通过缓存命中时的元数据核对发现。
- 浏览仅加载当前选中主图，快速换图有 160 ms 防抖，过时响应不会覆盖新图，不预读下一张、不后台补全全库。浏览器最多临时保存 12 MiB 压缩预览，5 分钟过期，离开页面清空；切换前仍向 NAS 核对当前版本。
- 补生成使用独立的一次性 CPU 解码进程，与识别互斥。结束即释放解码内存，不加载新质量模型，不增加空闲轮询。新扫描时增加的是受限尺寸的裁切、自动调整、JPEG 压缩和缓存写入时间，实际 NAS 耗时需安装后核对。
- 此文件是可重建的显示缓存，不需要随图库数据库备份；仅备份数据库不会包含这些图片。缓存被淘汰或丢失后，保留缩略图并显示补生成入口。

## 更新与验收

升级沿用已有离线依赖，不增加模型或安装包下载。先等待当前任务结束，按更新包校验、解压、升级、检查的组合命令运行。不会自动扫描、补生成全库或启用原片移动。

从现有图库选 1～3 张先验证：补生成、原图/自动调整对照、换图再返回、刷新后复用缓存；改一次框选，确认提示补生成且新预览范围正确。确认人工鸟种、标记、星级和原片只读挂载未变化。真实照片仅在用户浏览器显示，不提供给开发助手。
